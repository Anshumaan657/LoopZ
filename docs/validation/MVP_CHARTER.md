# Phase 1 MVP Charter

**Status:** Frozen for concierge validation  
**Charter version:** 1.0  
**Date:** 2026-08-26

## Problem statement

Freelancers and technical indie builders often give coding agents incomplete requests, then lose time to clarification, rework, unsupported completion claims, and repeated repair prompts.

## Hypothesis

A short risk-based interview followed by a confirmed contract, evidence-linked acceptance criteria, and a bounded repair task will produce more acceptable completed work with fewer avoidable corrections than the original rough request alone.

## Primary participant

A freelancer or technical indie builder who:

- Already uses an AI coding agent.
- Can run a small web-development task.
- Can understand basic test or build output.
- Can return the agent's report and evidence.
- Has authority to share the task information used in the study.

## Supported task profile

A new small web application or a clearly bounded feature in an existing web project that can be assessed through tests or inspectable evidence.

## Phase 1 product promise

> LoopZ turns a rough development request into a confirmed, verifiable task and checks the returned evidence against the original requirements.

## Claims permitted during Phase 1

- LoopZ structures requirements before implementation.
- LoopZ connects requirements to evidence expectations.
- LoopZ helps identify unsupported or incomplete work.
- LoopZ can generate a focused repair task.

## Claims prohibited until measured

- Guaranteed completion.
- Guaranteed verification.
- Guaranteed token savings.
- Guaranteed time savings.
- Identical output across agents.
- Support for every project or coding agent.

## Frozen workflow

```text
Original request
→ maximum five questions
→ confirmed scope
→ LoopSpec Lite
→ acceptance contract
→ agent task
→ returned evidence
→ criterion assessment
→ maximum two repair attempts
→ debrief
```

## Primary comparison

When a fair reset is possible:

```text
Baseline: original request → coding agent
LoopZ:    same request → confirmed LoopZ contract → same coding agent
```

## Primary outcome

Required acceptance criteria supported by submitted evidence at the end of the allowed run and repair budget.

## Supporting outcomes

- Clarification turns inside the coding agent.
- Human corrections.
- Repair attempts.
- Time to acceptable completion.
- Required-evidence coverage.
- Unsupported completion claims.
- Participant-reported usefulness.
- Intent to reuse.
- Willingness-to-pay signal and reasoning.

## Non-goals

- Building the automated interview engine.
- Running coding agents through LoopZ.
- Repository write access.
- Production deployment.
- Expert Mode.
- Multiple production adapters.
- Enterprise governance.

## Minimum fieldwork

- 5–10 eligible participants.
- 10–20 real tasks.
- At least five returned-evidence runs.
- At least three paired comparisons when technically fair.

## Decision owner

The founder owns the final go, pivot, extend, or stop decision. Raw evidence and negative results must remain visible in the decision record.
